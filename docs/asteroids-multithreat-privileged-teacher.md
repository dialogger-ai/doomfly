# Privileged multi-threat planning teacher

`asteroids.multithreat_privileged_teacher` is a development-only source of
action demonstrations. It reads exact ship and asteroid positions and
velocities from the game. For each decision it simulates candidate target
velocities for 72 game ticks, scores collisions, near misses, movement and
distance from the center, and holds the first turn/thrust/NOOP action for
three ticks before replanning. The actual environment supplies the outcome.
It has no neural model, no RGB-only perception, and no learned policy.

We froze the teacher implementation before checking eight new geometries
generated by `asteroids.multithreat_teacher_novel_check` (seed 20260925).
That check runs all modes on the same initialized scenes, with a five-second
horizon and firing disabled. Compact outcomes, scenario definitions, and
source/result hashes are in
`docs/evidence/asteroids-multithreat-privileged-teacher-v1.json`.

| Scenes | NOOP contacts | Earlier one-threat reference | RGB-only controller | New privileged teacher |
| --- | ---: | ---: | ---: | ---: |
| Original development (11) | 14 | 2 | 2 | 0 |
| Rotated layouts (10) | 14 | 2 | 5 | 0 |
| New seeded geometries (8) | 7 | 1 | 3 | 0 |

The new teacher completed all 29 horizons. It selected an active action on
32.2% of original development ticks, 33.2% of rotated ticks, and 33.0% of
new-geometry ticks. Both quiet development scenes and both quiet rotated
scenes were entirely NOOP; the two original blocked-gap cases in each split
ended with zero contacts. The new geometries vary starting positions,
headings, velocity, radius, and threat count, including receding decoys.
Eight generated layouts remain a small game-specific check, not a broad
generalization estimate. The rotated layouts had already been inspected
in the earlier RGB-controller work.

The current `multithreat_neural_action_capacity` assay uses the frozen
RGB-only controller and is unchanged, including its action target and
predeclared gate. Once that result arrives, a separate development run can
pair teacher actions with full-graph responses to the same RGB frames. The
teacher may initialize an interface policy, while a later reward-based
continuation must establish improvement from gameplay failures against a
matched frozen policy and neural-null controls. Only RGB frames and neural
state may enter the autonomous actor at evaluation; exact game telemetry
stays outside its observation. Some privileged actions may depend on rock
velocity that is ambiguous in a single frame, so a visual history and a
separate held-out geometry test are necessary. Neither teacher success nor
imitation by itself demonstrates fly learning or synaptic learning.

The Python commands below run a game-only benchmark and save compact JSON;
they require fresh output directories. The project workflow uses GitHub
Desktop's **Fetch origin**, then **Pull origin**, before a Mac terminal run.

```bash
RUN_DIR="outputs/asteroids/multithreat-privileged-teacher-$(date +%Y%m%d-%H%M%S)" && OPENBLAS_NUM_THREADS=1 caffeinate -i python -m asteroids.multithreat_privileged_teacher --split all --out "$RUN_DIR" && cp "$RUN_DIR/results.json" "$HOME/Downloads/doomfly-privileged-teacher-results.json" && ls -lh "$HOME/Downloads/doomfly-privileged-teacher-results.json"
```
